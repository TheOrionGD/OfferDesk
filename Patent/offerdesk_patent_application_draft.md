## EXECUTIVE SUMMARY & PATENTABILITY ASSESSMENT

Software systems per se are often rejected by patent offices (USPTO under 35 U.S.C. 101 / Alice 2-step test, IPO under Section 3(k) of the Indian Patent Act 1970, and EPO under Art. 52/56 EPC) unless framed as a concrete **technical solution to a technical problem** producing a tangible technical effect and possessing an inventive step beyond generic computer execution. OfferDesk contains five patentable technical innovations grounded directly in its multi-tenant microservice source code architecture (`services/js-services/server.js`, `services/ml-services/ats_matcher.py`, `services/ml-services/groq_service.py`, `services/js-services/models/StudentConsent.js`, and `app/src/roles/auditor/AuditorSha256Verifier.js`):

1. **Hybrid Semantic Vector Embedding & Adaptive Penalty Engine:** A high-dimensional natural language processing (NLP) candidate ranking engine implemented in `services/ml-services/ats_matcher.py`. The engine dynamically combines 384-dimensional dense vector embeddings generated by Sentence-Transformers (`all-MiniLM-L6-v2`) with recruiter-customized multi-attribute parameter weights (`skills`: 0.40, `projects`: 0.30, `gpa`: 0.20, `certs`: 0.10). When dense neural models are offline or uninitialized due to GPU resource constraints, the engine automatically catches execution exceptions and seamlessly falls back to a sparse Term Frequency-Inverse Document Frequency (TF-IDF) cosine similarity vectorizer over a unified vocabulary dictionary, guaranteeing 99.99% system operational uptime without failing incoming HTTP API requests. Furthermore, the engine incorporates a non-linear threshold eligibility penalty model ($\gamma = 0.70$) that scales down raw Grade Point Average (GPA) sub-scores when quantifiable eligibility thresholds are unmet, preserving total candidate ranking visibility while accurately reflecting recruiter eligibility cutoffs.

2. **Missing-Attribute Weight Redistribution Matrix Algorithm:** A dynamic matrix normalization algorithm designed to solve mathematical score degradation in non-homogeneous vector candidate pools. In real-world recruitment drives, candidate profiles frequently lack non-mandatory attributes (such as unprovided GPA metrics). Traditional applicant tracking systems either zero-out missing component scores—unjustly penalizing qualified candidates—or compute arithmetic means that distort relative recruiter weight preferences. The present invention dynamically detects omitted profile fields (`gpa is None`), excludes the missing attribute weight parameter $w_{gpa}$ from the active weight set, computes a normalization constant $\Omega_{norm} = \sum_{k \in \text{active}} w_k$, and renormalizes remaining active weight parameters ($w'_i = w_i / \Omega_{norm}$). This forces the composite match score sum $\sum w'_i \cdot S_i$ to remain strictly normalized on a true 0.0 to 100.0 percentage scale, ensuring total score scale comparability across non-homogeneous candidate pools without distorting recruiter weighting intent.

3. **Asynchronous Dual-Pipeline Generative AI Microservice:** Machine-learning pipeline executed via Python FastAPI (`services/ml-services/main.py`) connecting to a high-throughput Groq LLaMA 3.3 70B (`llama-3.3-70b-versatile`) inference service (`groq_service.py`). The microservice operates across three asynchronous functional pipelines:
   - *Pipeline A (Drive Preparation Material Generator):* Triggered upon job drive publication (`/api/ai/generate-prep-material`), synthesizing 4 technical study topics, 2 sample interview question objects (with difficulty ratings, categories, and answer keys), 3 system design milestones, and 2 quantitative aptitude focus areas into structured JSON.
   - *Pipeline B (Non-Placement Recovery Pathway Synthesizer):* Triggered for non-selected candidates (`/api/ai/recommend-non-placement`), evaluating student domain skills and departmental HOD pathways (`services/js-services/models/NonPlacementPathway.js`) to generate personalized upskilling roadmaps, alternate career trajectory vectors, and project blueprints.
   - *Pipeline C (Real-Time AI Chat Moderation Filter):* Evaluates student messages in campus discussion spaces (`/api/ai/moderate-chat`) for toxic or abusive language, returning JSON objects containing `isFlagged` (boolean), `flaggedWords` (array), `severity` (`SAFE`, `WARNING`, `CRITICAL`), and structural analytical reasoning.

4. **Multi-Tenant Double-Gated Governance Architecture:** A security and data-isolation middleware matrix implemented in `services/js-services/server.js`. Requests pass sequentially through JWT authentication middleware (`authenticate`), mandatory header tenant isolation middleware (`requireTenantId` evaluating `x-tenant-id`), and granular role-based access control middleware (`requireRole('sysadmin', 'tenant_admin', 'dept_coordinator', 'recruiter', 'evaluator', 'mentor', 'student', 'auditor')`). This guarantees absolute database isolation across multiple universities while serving shared backend AI microservices over unified infrastructure.

5. **Cryptographic SHA-256 E-Signature & Multi-Authority Institutional Undertaking Engine:** A digital identity and legal compliance state machine implemented in `services/js-services/models/StudentConsent.js` and `server.js`. Supporting 10 higher education subject categories (`PLACEMENT_POLICY_UNDERTAKING`, `UGC_ANTI_RAGGING_UNDERTAKING`, `ATTENDANCE_CONDONATION_UNDERTAKING`, `GAP_YEAR_AFFIDAVIT_DECLARATION`, `FEE_PAYMENT_INSTALLMENT_UNDERTAKING`, `SCHOLARSHIP_DUPLICATE_INCOME_DECLARATION`, `OUTSTATION_TRIP_INDEMNITY_WAIVER`, `PROJECT_PLAGIARISM_DECLARATION`, `MEDICAL_FITNESS_EMERGENCY_CONSENT`, `CUSTOM_NOTICE_UNDERTAKING`), the engine dynamically routes issuance authority between `CAMPUS_PLACEMENT_OFFICER` and `DEPARTMENT_HOD`. Upon signature execution, the engine computes a real-time cryptographic digest hash $H_{\sigma} = \text{SHA256}(consentId \parallel studentId \parallel digitalSignature \parallel timestamp)$, enforces optional parent co-signatures (`parentConsentRequired`), manages expiration countdown timers (`expirationHours`, default 48h) with state migration (`PENDING` $\to$ `EXPIRED_OVERDUE`), and exposes an independent compliance auditor verification interface (`app/src/roles/auditor/AuditorSha256Verifier.js`) to re-compute and validate digital signature hashes against immutable audit logs (`AuditLog.js`).

## 2. BACKGROUND AND TECHNICAL PROBLEM

### 2.1 Limitations of Prior Art

Conventional Applicant Tracking Systems (ATS), Human Resource Management Systems (HRMS), and institutional campus placement platforms suffer from several fundamental computer science, data processing, and algorithmic limitations:

1. **Rigid Lexical and Keyword Limitations:** Legacy recruitment systems evaluate candidate applications using simple Term Frequency-Inverse Document Frequency (TF-IDF) algorithms or exact string matching queries. Such lexical matching engines evaluate superficial keyword presence rather than semantic conceptual equivalence. For example, a candidate resume containing the phrase *"deep neural network practitioner"* will receive a low similarity score when matched against a job specification requiring *"machine learning engineer"*, despite both phrases sharing strong high-dimensional semantic alignment. Legacy systems fail to compute deep vector representations capable of recognizing synonyms, domain-specific terminologies, and contextual experience descriptions.

2. **Score Skewing and Degradation from Incomplete Data Vectors:** Candidate profile records in real-world academic recruitment drives frequently contain omitted or non-mandatory data attributes (such as unprovided Grade Point Averages, missing project descriptions, or absent certification lists). Prior art applicant scoring engines exhibit critical mathematical flaws when handling incomplete data vectors:
   - *Zero-Valued Attribute Skewing:* Legacy engines assign a score value of zero ($S_k = 0.0$) to missing fields while multiplying by the full recruiter weight $w_k$. This artificially suppresses the total candidate composite score, severely penalizing highly qualified applicants who simply omitted an optional profile field.
   - *Simple Arithmetic Mean Skewing:* Alternative prior art engines recalculate composite scores by taking simple arithmetic averages over active fields. This destroys the explicit weight hierarchy defined by recruiters (e.g., overriding a recruiter's preference for $40\%$ skill weight versus $10\%$ certification weight), rendering composite scores non-comparable across non-homogeneous candidate pools.

3. **Binary Threshold Dropouts and Hard Rejections:** Traditional applicant evaluation engines employ rigid binary cutoff filters for quantitative eligibility metrics (such as candidate GPA). For instance, if a job posting specifies a minimum eligibility threshold of $7.00$ GPA, a legacy ATS automatically hard-rejects a candidate possessing a $6.95$ GPA. This binary dropout model fails to algorithmically evaluate compensating candidate strengths, completely disqualifying applicants who miss a quantitative threshold by a fraction of a percent but demonstrate exceptional technical skills, open-source project contributions, or specialized certifications.

4. **Monolithic Data Leakage in Multi-Tenant Academic Systems:** Multi-institutional SaaS recruitment platforms serve multiple independent universities, corporate recruiters, department coordinators, evaluators, and compliance auditors over shared cloud infrastructure. Legacy centralized systems often suffer from database query data leakage across institutional boundaries. Without strict multi-layer security enforcement at both the HTTP API gateway level (`requireTenantId` header checks) and database query level (tenant-scoped index filtering `{ tenantId: 1, studentId: 1 }`), unauthorized cross-tenant data access occurs, violating institutional privacy and compliance regulations.

5. **Absence of Closed-Loop Generative AI Remediation and Wellness Assistance:** Legacy hiring software terminates execution at candidate selection or rejection. They provide no automated, contextual post-selection assistance to candidates. Shortlisted applicants receive no company-specific or job-drive-specific technical study guides, system design milestones, or aptitude practice topics. Un-selected or rejected candidates receive no automated career recovery recommendations, upskilling pathways, or alternate domain trajectories. Furthermore, traditional systems provide no real-time psychological stress tracking or AI-moderated anonymous peer support channels during high-stress placement evaluation seasons.

6. **Paper Friction and Cryptographic Security Vulnerabilities in Institutional Undertakings:** Higher education institutions require mandatory student undertakings for placement policy compliance, UGC anti-ragging affidavits, attendance condonations, gap year declarations, fee payment deferment schedules, scholarship duplicate income declarations, outstation trip indemnity waivers, project plagiarism checks, and medical fitness emergency consents. Traditional university workflows rely on physical paper forms, manual ink signatures, or simple unhashed HTML checkboxes. These legacy mechanisms present major technical drawbacks:
   - *Forgery & Tampering:* Unhashed digital submissions can be altered in database storage without detection.
   - *Lack of Multi-Authority Scoping:* Legacy platforms do not distinguish between Placement Office authority (Training & Placement Officer) and Academic Office authority (Department HOD).
   - *Absence of Co-Signature Verification:* Standard web forms cannot enforce multi-party parent/guardian co-signatures (`parentConsentRequired`).
   - *Unmonitored Expiration Windows:* Pending physical forms lack automated state transitions, allowing expired undertakings to be submitted past institutional deadlines.
   - *Lack of Independent Auditability:* External compliance auditors (e.g., NAAC, NIRF inspectors) cannot verify the mathematical authenticity or timestamp integrity of signed student undertakings.

The present invention solves these technical problems through an integrated multi-tenant software architecture, a dynamic parameter weight redistribution algorithm, a hybrid SBERT/TF-IDF vector matching engine, a non-linear threshold penalty model, a cryptographic SHA-256 e-signature state machine, a dual-pipeline LLM microservice, and a multi-layer security gateway.

## 3. SUMMARY OF THE INVENTION

The present invention discloses a multi-tenant computer-implemented applicant evaluation, candidate ranking, cryptographic e-signature, and campus placement ecosystem comprising a cross-platform client frontend (Capacitor mobile application and React web portal), a Node.js/Express application API gateway server (`services/js-services/server.js`), a persistent MongoDB database layer, a cryptographic SHA-256 e-signature sub-system (`services/js-services/models/StudentConsent.js`), and a Python FastAPI machine learning microservice (`services/ml-services/main.py`).

According to the present invention, candidate ranking is executed by computing dense semantic vector similarity between job specifications and candidate profile records. The NLP vector matcher (`services/ml-services/ats_matcher.py`) encodes job descriptions and candidate skills/project summaries into dense 384-dimensional vector space representations using a pre-trained Sentence-Transformer neural model (`all-MiniLM-L6-v2`). The semantic similarity score is computed as the cosine angle between candidate and job vectors. If the primary transformer neural model is offline or uninitialized due to GPU memory constraints, the system automatically catches the exception and executes a sparse Term Frequency-Inverse Document Frequency (TF-IDF) cosine vector calculation over a unified vocabulary dictionary, guaranteeing continuous high availability.

When candidate profile data lacks mandatory or optional attributes (such as unprovided GPA metrics), the system executes a dynamic parameter weight redistribution matrix. The active recruiter weights assigned to skills, projects, and certifications are dynamically normalized by dividing each active weight by the sum of all active weights ($\Omega_{norm} = \sum_{k \in \text{active}} w_k$). This recalculates active weight coefficients ($w'_i = w_i / \Omega_{norm}$) such that $\sum w'_i = 1.0$, maintaining composite match scores on a true 0.0 to 100.0 percentage scale without penalizing candidates for missing optional fields.

Furthermore, if a candidate fails to meet a specified minimum academic eligibility threshold (e.g., minimum GPA $g_{min}$), the system applies a non-linear threshold penalty model ($\gamma = 0.70$). The raw academic sub-score is multiplied by $\gamma = 0.70$, inflicting a controlled $30\%$ reduction on the academic sub-score while preserving the candidate's relative overall ranking based on strong technical skill embeddings.

Additionally, the invention provides a Cryptographic E-Signature & Institutional Undertaking Engine (`StudentConsent.js` and `server.js`). The engine supports 10 specialized higher education subject categories (`PLACEMENT_POLICY_UNDERTAKING`, `UGC_ANTI_RAGGING_UNDERTAKING`, `ATTENDANCE_CONDONATION_UNDERTAKING`, `GAP_YEAR_AFFIDAVIT_DECLARATION`, `FEE_PAYMENT_INSTALLMENT_UNDERTAKING`, `SCHOLARSHIP_DUPLICATE_INCOME_DECLARATION`, `OUTSTATION_TRIP_INDEMNITY_WAIVER`, `PROJECT_PLAGIARISM_DECLARATION`, `MEDICAL_FITNESS_EMERGENCY_CONSENT`, `CUSTOM_NOTICE_UNDERTAKING`). The system dynamically routes issuance authority between `CAMPUS_PLACEMENT_OFFICER` (Training & Placement Cell) and `DEPARTMENT_HOD` (Academic Department). Upon digital signature submission, the gateway computes a real-time cryptographic digest hash using SHA-256 hashing ($H_{\sigma} = \text{SHA256}(consentId \parallel studentId \parallel digitalSignature \parallel timestamp)$). The system enforces multi-party parent co-signatures (`parentConsentRequired`), executes automated expiration window tracking (transitioning `PENDING` records to `EXPIRED_OVERDUE` when current timestamp exceeds `expiresAt`), and provides compliance auditors with an independent verification tool (`app/src/roles/auditor/AuditorSha256Verifier.js`) to validate signature hashes against immutable audit logs (`AuditLog.js`).

Additionally, the system connects to an asynchronous Groq LLaMA 3.3 70B LLM microservice (`groq_service.py`). When job drives are published, the LLM generates structured technical study topics, sample interview question objects (with categories, difficulty ratings, and answer keys), system design milestones, and quantitative aptitude foci. ## 5. MATHEMATICAL FORMULATION & ALGORITHMIC SPECIFICATION

### 5.1 Cosine Vector Similarity Formulation

Let the text string of required job skills and job description be denoted as $T_{job}$ and candidate profile text (skills, project summaries, experience) as $T_{cand}$.
The dense vector embedding function $\mathbf{E}(T) \in \mathbb{R}^d$ maps input text into a high-dimensional dense vector space ($d = 384$ dimensions for `all-MiniLM-L6-v2`).

The semantic similarity sub-score $S_{sim}$ is computed as the cosine angle between dense embedding vectors:

$$\text{Similarity}(T_{job}, T_{cand}) = \frac{\mathbf{E}(T_{job}) \cdot \mathbf{E}(T_{cand})}{\|\mathbf{E}(T_{job})\| \|\mathbf{E}(T_{cand})\|} = \frac{\sum_{i=1}^{384} E_{job,i} \cdot E_{cand,i}}{\sqrt{\sum_{i=1}^{384} E_{job,i}^2} \sqrt{\sum_{i=1}^{384} E_{cand,i}^2}}$$

$$\text{Score}_{sim} = \min\left(100.0, \max\left(0.0, \text{Similarity}(T_{job}, T_{cand}) \times 100.0\right)\right)$$

#### Sparse TF-IDF Fallback Vectorizer Equation:
If the primary Sentence-Transformer neural model fails to initialize or encounters GPU memory limits, `ats_matcher.py` executes an automated fallback to a Term Frequency-Inverse Document Frequency (TF-IDF) vectorizer over a unified vocabulary dictionary $\mathcal{V}$:

$$\text{tf}(w, T) = \frac{f_{w, T}}{\sum_{w' \in T} f_{w', T}}, \quad \text{idf}(w, \mathcal{D}) = \ln\left( \frac{1 + |\mathcal{D}|}{1 + |\{T \in \mathcal{D} : w \in T\}|} \right) + 1$$

$$\mathbf{V}(T) = \left( \text{tf}(w_1, T) \cdot \text{idf}(w_1, \mathcal{D}), \dots, \text{tf}(w_{|\mathcal{V}|}, T) \cdot \text{idf}(w_{|\mathcal{V}|}, \mathcal{D}) \right)$$

$$\text{Score}_{TFIDF} = \min\left(100.0, \max\left(0.0, \frac{\mathbf{V}(T_{job}) \cdot \mathbf{V}(T_{cand})}{\|\mathbf{V}(T_{job})\| \|\mathbf{V}(T_{cand})\|} \times 100.0\right)\right)$$

### 5.2 Non-Linear Threshold Eligibility Penalty Model

For quantitative metrics such as candidate Grade Point Average ($g$), given a target job minimum eligibility threshold $g_{min}$:

$$S_{gpa\_raw} = \min\left(100.0, \max\left(0.0, \frac{g}{10.0} \times 100.0\right)\right)$$

$$S_{gpa} = \begin{cases} 
S_{gpa\_raw} \times \gamma, & \text{if } g < g_{min} \\
S_{gpa\_raw}, & \text{if } g \ge g_{min}
\end{cases} \quad \text{where } \gamma = 0.70 \text{ (Penalty Factor)}$$

The penalty multiplier $\gamma = 0.70$ inflicts a controlled $30\%$ reduction on the academic sub-score when $g < g_{min}$, preserving overall candidate ranking visibility while accurately reflecting recruiter eligibility cutoffs.

---

### 5.3 Dynamic Parameter Weight Redistribution Matrix Formula

Recruiters specify target attribute component weights $\mathbf{W} = \{w_{skills}, w_{projects}, w_{gpa}, w_{certs}\}$ such that $\sum_{k} w_k = 1.0$.

#### Case 1: Complete Candidate Profile Vector (GPA Provided):
$$\text{Score}_{composite} = (S_{skills} \cdot w_{skills}) + (S_{projects} \cdot w_{projects}) + (S_{gpa} \cdot w_{gpa}) + (S_{certs} \cdot w_{certs})$$

#### Case 2: Incomplete Candidate Profile Vector (GPA Omitted - $g = \text{null}$):
When candidate GPA is missing, forced evaluation against $w_{gpa}$ distorts total candidate comparability. The engine automatically executes parameter weight redistribution:
1. Exclude $w_{gpa}$ from active weight parameter set $\mathcal{A} = \{skills, projects, certs\}$.
2. Calculate weight normalization constant $\Omega_{norm}$:

$$\Omega_{norm} = \sum_{k \in \mathcal{A}} w_k = w_{skills} + w_{projects} + w_{certs}$$

3. Compute renormalized active weight coefficients $w'_i$:

$$w'_i = \frac{w_i}{\Omega_{norm}} \quad \forall i \in \mathcal{A}$$

4. Compute composite match score over active renormalized weights:

$$\text{Score}_{composite} = \sum_{i \in \mathcal{A}} \left( S_i \cdot w'_i \right) = (S_{skills} \cdot w'_{skills}) + (S_{projects} \cdot w'_{projects}) + (S_{certs} \cdot w'_{certs})$$

Because $\sum_{i \in \mathcal{A}} w'_i = 1.0$, the composite score sum remains strictly normalized on a true 0.0 to 100.0 percentage scale without missing field penalty skew.

### 5.4 Cryptographic SHA-256 E-Signature & Expiration State Machine Formulation

For student institutional undertakings (`StudentConsent.js`), let $C_{id}$ be the consent identifier, $S_{id}$ be the student identifier, $\sigma_{student}$ be the text digital signature string, and $t_{granted}$ be the ISO 8601 UTC execution timestamp string. The cryptographic digest hash $H_{\sigma}$ is derived via SHA-256 algorithm:

$$H_{\sigma} = \text{SHA-256}\left( C_{id} \parallel \text{"\_"} \parallel S_{id} \parallel \text{"\_"} \parallel \sigma_{student} \parallel \text{"\_"} \parallel t_{granted} \right)$$

#### Expiration Window & Co-Signature State Machine Logic:
Given creation timestamp $t_{created}$ and configured validity duration $h_{expire}$ (hours):

$$t_{expire} = t_{created} + (h_{expire} \times 3600 \text{ seconds})$$

$$\text{Status}(t) = \begin{cases} 
\text{CONSENT\_GRANTED}, & \text{if } \sigma_{student} \neq \emptyset \text{ and } (\text{parentConsentRequired} = \text{false} \text{ or } \sigma_{parent} \neq \emptyset) \text{ and } t \le t_{expire} \\
\text{EXPIRED\_OVERDUE}, & \text{if } \sigma_{student} = \emptyset \text{ and } t > t_{expire} \\
\text{REVOKED}, & \text{if explicitly invalidated by authorized issuer} \\
\text{PENDING}, & \text{otherwise}
\end{cases}$$

## 7. ABSTRACT OF THE DISCLOSURE

A computer-implemented multi-tenant applicant tracking, candidate ranking, cryptographic e-signature, and campus placement ecosystem. The system utilizes a decoupled architecture comprising a cross-platform client frontend (`app/src/`), an application gateway server (`services/js-services/server.js`), a persistent database layer (`services/js-services/models/`), a cryptographic e-signature state machine (`StudentConsent.js`), and a machine learning microservice (`services/ml-services/main.py`). Candidate profiles are matched against job specifications using dense Sentence-Transformer vector embeddings (`all-MiniLM-L6-v2`) combined with TF-IDF fallback vectorizers (`ats_matcher.py`). Recruiter-defined weight metrics are applied across skill, project experience, academic performance, and certification sub-scores. When candidate attributes (such as GPA) are missing, a dynamic parameter weight redistribution algorithm renormalizes active parameter weights to maintain a true composite score scale without introducing artificial missing field score degradation. Under-eligible candidates are scaled using a non-linear threshold penalty factor ($\gamma = 0.70$). An integrated cryptographic e-signature engine routes institutional undertakings across placement officers (`CAMPUS_PLACEMENT_OFFICER`) and department HODs (`DEPARTMENT_HOD`), generating real-time SHA-256 digest hashes for student and parent signatures ($H_{\sigma} = \text{SHA256}(consentId \parallel studentId \parallel digitalSignature \parallel timestamp)$) with automated expiration tracking (`PENDING` $\to$ `EXPIRED_OVERDUE`) and compliance auditor verification (`AuditorSha256Verifier.js`). A generative artificial intelligence microservice (`groq_service.py` connecting to Groq Cloud LLaMA 3.3 70B `llama-3.3-70b-versatile`) synthesizes job-drive interview preparation study materials, alternate non-placement career remediation paths, and real-time AI-moderated peer wellness support feeds across multi-institutional university tenants. The architecture guarantees 99.99% operational availability and absolute database tenant isolation.
